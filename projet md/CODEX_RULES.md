# Règles de développement pour Codex

1. Lire tous les documents de contexte avant de coder.
2. Ne pas ajouter de fonctionnalité hors MVP sans demande explicite.
3. Le backend est l'autorité sur l'état.
4. Le LLM ne décide jamais seul d'une transition irréversible.
5. Toute sortie LLM doit être structurée et validée.
6. Ne jamais exposer les secrets API côté client.
7. Garder le fournisseur LLM remplaçable.
8. Préférer des fonctions pures et testables pour l'orchestrateur.
9. Écrire des tests pour les règles critiques.
10. Aucun conseil marketing ne doit être généré au prospect.
11. Aucun jugement sur une agence précédente.
12. Aucun prix, délai ou livrable promis par l'IA.
13. La consultation doit pouvoir être interrompue proprement.
14. Le brief doit pouvoir être reconstruit à partir de données structurées.
15. Avant une modification importante, expliquer brièvement le plan.
16. Après chaque étape, indiquer les fichiers changés et les tests exécutés.
